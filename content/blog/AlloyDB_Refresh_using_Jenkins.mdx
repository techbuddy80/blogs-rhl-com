# Automating AlloyDB Cluster Refresh Across GCP Projects Using Jenkins

Refreshing development or test databases with production data is a common operational task. Performing this manually is time-consuming and error-prone, especially when your production and non-production AlloyDB clusters reside in different Google Cloud projects.

In this article, we'll build a Jenkins pipeline that automates the refresh process while keeping everything repeatable and auditable.

> **Note**
>
> This article uses placeholder project names and IDs. Replace them with values from your own environment.

---

# Architecture

```text
                 +----------------------+
                 |     Jenkins Server   |
                 +----------+-----------+
                            |
                            |
                    Service Account
                            |
          +-----------------+------------------+
          |                                    |
          |                                    |
+---------v----------+              +----------v----------+
| Production Project |              | Development Project |
|                    |              |                     |
| AlloyDB Cluster    |              | AlloyDB Cluster     |
|                    |              |                     |
| Latest Backup      |------------->| Restore Backup      |
+--------------------+              +---------------------+
```

# Prerequisites

Before starting, ensure you have the following:

- Jenkins server
- Google Cloud SDK installed on Jenkins
- Jenkins agent with network connectivity to Google Cloud APIs
- Production AlloyDB cluster
- Development AlloyDB cluster
- IAM permissions for AlloyDB administration
- Service Account JSON key (or preferably Workload Identity)

Example environment:

| Resource            | Example           |
| ------------------- | ----------------- |
| Production Project  | `prod-project-id` |
| Development Project | `dev-project-id`  |
| Production Cluster  | `prod-cluster`    |
| Development Cluster | `dev-cluster`     |
| Region              | `us-central1`     |

# Step 1: Create a Service Account

Create a dedicated service account for Jenkins.

Example:

```bash
gcloud iam service-accounts create jenkins-alloydb \
    --display-name="Jenkins AlloyDB Automation"
```

Grant the minimum required permissions.

Recommended roles:

- AlloyDB Admin
- Viewer
- Compute Network Viewer

If restoring across projects, grant permissions in **both** projects.

---

# Step 2: Download the Service Account Key

```bash
gcloud iam service-accounts keys create key.json \
    --iam-account=jenkins-alloydb@prod-project-id.iam.gserviceaccount.com
```

Store this securely inside Jenkins Credentials rather than directly on disk.

# Step 3: Install Google Cloud SDK on Jenkins

Verify installation:

```bash
gcloud version
```

Authenticate:

```bash
gcloud auth activate-service-account \
    --key-file=key.json
```

# Step 6: Create Pipeline Parameters

The pipeline accepts the following parameters.

| Parameter       | Description         |
| --------------- | ------------------- |
| PROD_PROJECT_ID | Production project  |
| DEV_PROJECT_ID  | Development project |
| REGION          | AlloyDB region      |
| PROD_CLUSTER    | Production cluster  |
| DEV_CLUSTER     | Development cluster |

---

# Step 7: Jenkins Pipeline

```groovy
pipeline {

    agent any

    parameters {

        string(
            name: 'PROD_PROJECT_ID',
            defaultValue: 'prod-project-id'
        )

        string(
            name: 'DEV_PROJECT_ID',
            defaultValue: 'dev-project-id'
        )

        string(
            name: 'REGION',
            defaultValue: 'us-central1'
        )

        string(
            name: 'PROD_CLUSTER',
            defaultValue: 'prod-cluster'
        )

        string(
            name: 'DEV_CLUSTER',
            defaultValue: 'dev-cluster'
        )
    }

    environment {
        GOOGLE_APPLICATION_CREDENTIALS = credentials('gcp-alloydb-sa')
    }

    stages {

        stage('Authenticate') {

            steps {

                sh """
                gcloud auth activate-service-account \
                    --key-file=$GOOGLE_APPLICATION_CREDENTIALS
                """
            }
        }

        stage('Locate Latest Backup') {

            steps {

                script {

                    env.BACKUP = sh(
                        script: """
                        gcloud alloydb backups list \
                        --project=${params.PROD_PROJECT_ID} \
                        --region=${params.REGION} \
                        --sort-by=~createTime \
                        --limit=1 \
                        --format='value(name)'
                        """,
                        returnStdout: true
                    ).trim()

                    echo "Backup Found: ${env.BACKUP}"
                }
            }
        }

        stage('Restore Backup') {

            steps {

                sh """
                gcloud config set project ${params.DEV_PROJECT_ID}

                gcloud alloydb backups restore \
                    ${env.BACKUP} \
                    --cluster=${params.DEV_CLUSTER}
                """
            }
        }

        stage('Verify') {

            steps {

                sh """
                gcloud alloydb clusters describe \
                    ${params.DEV_CLUSTER} \
                    --project=${params.DEV_PROJECT_ID}
                """
            }
        }

    }

    post {

        success {
            echo "Refresh Completed Successfully"
        }

        failure {
            echo "Refresh Failed"
        }

    }

}
```

---

# Step 8: Execute the Pipeline

Run the Jenkins job.

Example values:

```
PROD_PROJECT_ID = prod-project-id

DEV_PROJECT_ID = dev-project-id

REGION = us-central1

PROD_CLUSTER = prod-cluster

DEV_CLUSTER = dev-cluster
```

Jenkins will

1. Authenticate to Google Cloud
2. Locate the newest backup
3. Switch to the destination project
4. Restore the backup
5. Verify the cluster status

# Security Best Practices

Avoid storing credentials directly in pipeline scripts.

Recommended practices:

- Use Jenkins Credentials
- Prefer Workload Identity over service account keys when possible
- Grant least-privilege IAM roles
- Rotate credentials regularly
- Restrict Jenkins job permissions
- Enable Cloud Audit Logs
- Encrypt backups where applicable

# Troubleshooting

## Permission Denied

Verify IAM roles.

```bash
gcloud projects get-iam-policy prod-project-id
```

---

## No Backups Found

Verify backup availability.

```bash
gcloud alloydb backups list \
    --project=prod-project-id
```

---

## Authentication Failed

Verify the active account.

```bash
gcloud auth list
```

---

## Cluster Restore Fails

Check cluster operations.

```bash
gcloud alloydb operations list \
    --project=dev-project-id
```

Automating AlloyDB refreshes with Jenkins eliminates repetitive manual work and provides a repeatable, auditable process for keeping non-production environments current.
